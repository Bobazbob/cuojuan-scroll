# 底层验证记录

以 H01 v02 契约和 B 的 H04 v01 正式数据为输入。浏览器为 Chromium，本地由 Node 静态服务打开生产构建的 core-demo.html。

| 实际检查 | 结果 |
|---|---|
| H01 正式校验器 | 故事 4／结局 8，全部通过；首组对象与原 H02 一致 |
| Node 底层逐分支检查 | 四组合、八个选项引用、非法/合法放置、重复选择拦截、效果队列、卡片数据、八次重玩和每局 AbortSignal 通过 |
| Node 资源加载状态 | 缺失、等待、加载中、失败、就绪、同 ID 并发合并、失败重试和缓存通过 |
| Chromium 实际交互 | H04 八条分支共 48 次阶段按钮操作、八次重玩，脚本异常 0。读取卡片与效果字段时与引擎一致 |
| H03 功能对照 | 根入口仍可打开并看到“展开画卷”按钮 |

第一轮使用测试候选站位，浏览器检查了正式 PNG 为空时的缺失输出。H06 入库后，重新生产构建并点击了全部八条分支，实际解码结局使用的已验收人物 PNG。

H07、H08 入库后，实际用四层正式 PNG、角色 PNG 和库内站位重跑了四组八条分支。浏览器中点击画布的非法点不前进，有效点吸附到对应脚底，每条结局加载五张实际 PNG。表情变化的分支画布像素有相应变化，表情仍为 neutral 的分支不变。重玩关闭旧画布与结局，八条无脚本异常。以正式源图重新合成的两张静态四层预览和 B 的预览逐像素一致，前景在两块 UI 安全区内均为透明。

H09 入库后再构建，生产版 Chromium 用相同正式坐标重跑八条分支和重玩，并在浏览器中解码全部 17 张入库 PNG，宽高与登记一致、脚本异常 0。见 [实际记录](../asset-library/visual/a-browser-verification.txt)。
