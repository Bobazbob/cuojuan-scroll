## 需要修复的问题

没有发现P0。以下均归A／Claude页面实现或发布入口；本轮没有B源素材缺陷。

### V01 · P1 · 阅读区遮罩同时淡化正文、标题和按钮

- 复现：公网1600×900 → 展开画卷 → 花果山 → 林黛玉 → 点击圆环 → 看开场；任一结局同样出现。
- 位置：原始截图正文首字约(x171,y750)，标题约(x171,y729)，继续按钮约(x1344–1429,y740–784)。文字和按钮都位于视觉规范允许区，但被容器的左右渐隐影响。
- 实际：第一行、第二行的前几字明显变淡；标题首字和右侧按钮边缘也变淡。数据完整不代表阅读可读性通过。
- 预期：纸面背景可以柔和渐隐，文字、按钮、焦点边线保持完整清晰。
- 最小建议：`src/scroll/scroll.css` 的 `.reader` 渐隐移至独立背景伪元素，内容层不应用mask。保留现有轻纸面和原文，不以新增厚矩形面板替代。
- 证据：[原始公网开场](public_desktop_bury/04_intro_1.png)、[结局末页](public_desktop_bury/07_ending_2.png)、[标注与诊断对照](issue-V01-mask.png)。对照下半图仅在浏览器DOM临时关闭mask，用来定位原因；**不是已修好的产品或验收通过图**。

### V02 · P1 · 窄屏画境和人物被非等比缩放

- 复现：公网模拟390×844或320×568 → 按上流程放置黛玉；布局稳定后读取实际DOM尺寸。
- 实际390宽：程序给卷轴宽374.4px、舞台高210.6px；实际受页面12px左右内边距限制，宽366px、高210.594px，比值1.73794；应为1.77778。图像纵向相对拉长约2.292%，人物比值0.73314，偏离3:4。
- 实际320宽：程序宽307.2px、高172.8px；实际宽296px、高172.797px，比值1.71299，纵向相对拉长约3.782%；人物比值0.72259。
- 预期：任何视口整景16:9、人物3:4，共享同一等比变换。不能用“脚底换算仍为675”替代比例检查。
- 最小建议：`main.ts layout()` 依据容器实际可用宽度（包含真实padding／safe-area）确定宽度，再计算高度；也可令舞台受 `aspect-ratio:16/9` 约束。避免宽度被CSS二次压缩而高度仍按旧宽算。修后复验390/320及横屏，不改PNG或锚点。
- 证据：[尺寸JSON](diagnostics.json)、[390原图](diagnostic-actual-390.png)、[320原图](diagnostic-actual-320.png)、[标注图](issue-V02-small-screen.png)。

- 最小建议：A决定正式根入口指向现有 `daiyu-huaguoshan.html`；在修改前，所有分享使用完整正式URL。B不改配置、不推送或发布。

### V03 · P2 · 窄屏正文被侧边按钮挤成细列，分页测量与显示不一致

- 复现：390或320宽进入开场。390宽第一开场页正文宽217.109px、约5行；320宽正文宽147.109px、约6行。右侧“继续”持续占一列，阅读有较多碎行。
- 实际：正文能读完且未丢字，但下方布局目标4行的测量与实际5／6行不一致；横屏844×390下部分阅读区还需要纵向滚动，不能称一屏完整显示。
- 预期：手机正文用足可读宽度，翻页按钮在正文下方，按最终实际宽度分页；保持至少18px，而非继续缩字。
- 最小建议：下方阅读布局在窄宽时上下排正文／操作；先建立按钮后按最终文字宽度测量。无需改故事字数或文案。
- 证据：[390开场](touch_portrait_bury/04_intro_1.png)、[320开场](diagnostic-actual-320.png)、[844横屏结局](touch_landscape_bury/07_ending_1.png)、`diagnostics.json`。

### V04 · P2 · 结局翻页后键盘焦点丢到BODY

- 复现：1600宽用Enter依次进入第一结局 → 结局1/2页按Enter“继续” → 再按Enter。
- 实际：进入2/2页后activeElement为BODY，再按Enter无动作；Tab可重新找到重玩，故不是键盘死路。新“重玩”按钮未继承原翻页位置的焦点。
- 预期：原文换页后焦点留在新阅读操作上，键盘用户可连续操作且看到焦点框。
- 最小建议：`renderReader()` 的分页回调替换按钮后，将焦点放回新生成的阅读按钮；仅在需要时处理焦点，不强制滚屏。
- 证据：`browser-results.json` 的keyboard步骤、[翻页后重新Tab的截图](keyboard/02_after_tab.png)。

### V05 · P2 · 窄屏右上重玩超出场景控制安全框

- 复现：390×844，按钮实际页面坐标约(x287.484,y26.938,w68.563,h44)，换算到舞台为约x1204–1504、y64–252；契约控制框只到y108。320宽也有同类问题。
- 实际：44px触控面积得到保留，按钮可点、没有挡黛玉脸，但侵入右上山水／瀑布区。1600宽下按钮底约y110.4，也略越过y108。
- 预期：保持44px可操作尺寸，同时不侵入画境；窄屏既然已有下方操作区，可将常驻重玩移出画境。桌面微调上边距即可。
- 最小建议：小屏重玩放在画境下独立操作区；不要把按钮等比缩到44px以下。落花采样在右上控制框内偶有非零像素（本轮各case最大172场景像素），也可裁出固定控制区；本轮未观察到点击受阻。
- 证据：[390选择页](touch_portrait_bury/05_choice.png)、`browser-results.json` 的按钮bounds与effectSamples。此为实现排布问题，不通过重画远山解决。
